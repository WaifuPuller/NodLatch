Nodlatch Build Playbook

How the demo works end to end on your laptop and iQOO phone, which files exist, and the order to build them in during the 26–27 September event. Nothing here is code; code starts when the clock starts.

The three programs

Two run on the laptop, one on the phone. The agent is never allowed to write into the real repository; it only ever writes into a scratch copy. Only the executor writes to the real repo, and only after the phone has signed a decision.

Laptop

AI coding agent

Claude Code (claude -p), Antigravity, or a local model via Ollama. Gets the task and a scratch copy of the repo. Untrusted.

Laptop

Nodlatch executor

Small Python CLI you write at the event: propose, execute. Builds proposals, verifies decisions, applies, tests, rolls back.

iQOO phone

Nodlatch app

Shows the proposal, one card per action, approve/deny, read-back, signs the decision with a key that never leaves the phone.

Office Kit is not a program you write. It is the event-provided bridge (file transfer, shared clipboard, screen mirroring) that moves three small JSON files between the two devices. The executor never trusts a file because it came through Office Kit; it re-checks everything.

Best case, start to finish

"Best case" hides three unknowns you cannot resolve until you hold the loaner phone: whether Office Kit file transfer and clipboard behave the way steps 3 and 6 need, whether the phone can do Ed25519 signing and a fingerprint prompt easily, and whether the executor may run on the laptop during a Red Light evaluation. Test all three in hour one.

The three files

Keep them small, single-line-safe (base64 the content blobs if they go through the clipboard), and keep the exchange folder outside the git repo.

// proposal.json  (laptop → phone)
{
  "proposal_id": "P-001",
  "repo": "demo-repo",
  "created_at": "2026-09-26T12:40:00+05:30",
  "expires_at": "2026-09-26T12:50:00+05:30",
  "actions": [
    { "action_id": "A1", "type": "modify_file", "path": "src/auth.py",
      "expected_old_sha256": "9f2c…", "new_file_sha256": "b71e…",
      "summary": "Fix token expiry comparison in verify_token()", "risk": "low" },
    { "action_id": "A2", "type": "modify_file", "path": "config.py",
      "expected_old_sha256": "0a44…", "new_file_sha256": "c3d9…",
      "summary": "Change SESSION_TTL from 3600 to 86400", "risk": "medium" }
  ],
  "test_suites": [ { "id": "auth-suite-v1", "min_tests": 17 } ],
  "review_view": { "A1": "…redacted diff text…", "A2": "…" },
  "commitment_sha256": "e88a…"   // hash of everything above except review_view
}

// decision.json  (phone → laptop)
{
  "decision_id": "D-001", "proposal_id": "P-001", "commitment_sha256": "e88a…",
  "approved": ["A1"], "denied": ["A2"], "required_test_suite": "auth-suite-v1",
  "signed_at": "2026-09-26T12:42:10+05:30",
  "signature": "base64-ed25519-over-exact-bytes-of-the-fields-above"
}

// receipt.json  (laptop → phone, informational)
{ "decision_id": "D-001", "status": "APPLIED", "applied": ["A1"],
  "denied": ["A2"], "tests": "17 passed", "finished_at": "…" }

The new file contents themselves never travel to the phone; they stay in nodlatch/store/<sha256> on the laptop. The phone authorizes a hash, and the executor checks the bytes against it.

Executor checks, in this order

Every check that fails prints one status line and stops. Nothing is written before check 6 has marked the decision as used.

  • 1Parse decision.json strictly (unknown fields → reject)REJECTED_MALFORMED
  • 2Verify Ed25519 signature against the paired phone public keyREJECTED_BAD_SIGNATURE
  • 3proposal_id matches a stored proposal and its commitment hashREJECTED_PROPOSAL_MISMATCH
  • 4Laptop clock ≤ expires_atREJECTED_EXPIRED
  • 5decision_id not in used_decisions.jsonREJECTED_REPLAY
  • 6Write decision_id to used_decisions.json now (single-use, before any mutation)—
  • 7approved + denied IDs all exist; approved set non-emptyREJECTED_ZERO_ACTIONS
  • 8For each approved action: stored bytes hash == new_file_sha256REJECTED_ARTIFACT_HASH_MISMATCH
  • 9For each approved action: current file hash == expected_old_sha256REJECTED_SOURCE_STATE_MISMATCH
  • 10Path is relative, no .., no symlink, not in protected list (.env*, *.pem, tests/**, pytest.ini…)REJECTED_PROTECTED_TARGET
  • 11Resolve required_test_suite from the executor's own trusted_suites.json (never from the phone or agent)REJECTED_UNKNOWN_SUITE
  • 12Apply approved bytes in a staging copy; run the suite; require exit 0 and ≥ min_tests collectedTESTS_FAILED_NOT_APPLIED
  • 13Re-check step 9 on the real tree, back up old bytes to backups/D-001/, write new bytes, verify hashEXECUTION_ERROR_ROLLED_BACK
  • 14Write receipt.jsonAPPLIED

Build order: seven slices

Evaluation Round 1 is about eight hours after hacking starts, so slice 0 must be demoable first, even though it has no security in it yet. Each slice adds files without rewriting the previous ones. Times are rough and assume three people working in parallel where the columns allow.

Slice 0 · The vertical slice

~2.5 h · no signing, no AI, no checks
Laptop files
  • demo-repo/src/auth.py, demo-repo/config.py, demo-repo/tests/test_auth.py (small, ~17 tests)
  • nodlatch/propose.py — for now takes a hand-written "new auth.py", writes exchange/out/proposal.json
  • nodlatch/execute.py — reads exchange/in/decision.json, copies approved bytes into the repo
  • nodlatch/store/, exchange/ (outside the repo)
Phone files
  • app/index.html — one page: "Import proposal" button, one card per action with Approve/Deny, "Export decision" button
  • app/app.js — parse proposal, build decision JSON, show it / copy it
  • Pick the shell now: PWA in the phone browser, or a minimal Android/Flutter app. Whichever the first-hour test says is faster.
Done when: you tap Approve on the phone and one file changes on the laptop. Show this to a mentor before touching anything else.

Slice 1 · Exactness

~1.5 h
Laptop files
  • nodlatch/hashing.py — sha256 of files and of the proposal commitment
  • propose.py now records expected_old_sha256, new_file_sha256, commitment_sha256
  • execute.py adds checks 3, 7, 8, 9 and the status codes
Phone files
  • app.js shows action IDs, paths, summaries; decision carries commitment_sha256
  • Read-back screen: "Authorizing A1 only" before Export
Done when: flipping one byte in store/ after approval makes execute print REJECTED_ARTIFACT_HASH_MISMATCH. That is demo 2.

Slice 2 · Default deny

~1 h
Laptop files
  • nodlatch/policy.py — protected path list, path normalisation
  • nodlatch/state/used_decisions.json — checks 4, 5, 6, 10
  • Strict JSON parsing (check 1)
Phone files
  • app.js adds decision_id, signed_at; shows proposal expiry countdown
Done when: running execute twice on the same decision prints REJECTED_REPLAY. That is demo 4.

Slice 3 · Test gate and rollback

~1.5 h
Laptop files
  • nodlatch/trusted_suites.json — {"auth-suite-v1": {"cmd": ["pytest","tests/test_auth.py","-q"], "min_tests": 17}}
  • nodlatch/testgate.py — staging copy, run suite, parse count, checks 11, 12
  • nodlatch/backups/ — check 13, restore on failure
  • A second fixture proposal whose change breaks a test
Phone files
  • Suite picker on the read-back screen (one option is fine)
  • receipt view: status, applied, denied, test count
Done when: the breaking fixture prints TESTS_FAILED_NOT_APPLIED and the repo is byte-identical to before. That is demo 3.

Slice 4 · Signing and pairing

~2 h, fingerprint time-boxed to 1 h
Laptop files
  • nodlatch/verify.py — Ed25519 verify (PyNaCl or cryptography)
  • nodlatch/trusted_keys/phone.pub — written once at pairing
  • nodlatch pair — show the phone's public key fingerprint on both screens, human compares, confirm
Phone files
  • app/keys.js — generate keypair once, store private key on the phone (WebCrypto Ed25519 if the browser has it, else tweetnacl-js; Android Keystore if native)
  • Sign the exact serialized bytes of the decision fields; never re-serialize on the laptop
  • Optional: biometric prompt before signing. If it doesn't work in an hour, ship a confirm tap and say so.
Done when: a decision edited after signing prints REJECTED_BAD_SIGNATURE, and an unedited one still applies.

Slice 5 · The real agent

~2 h
Laptop files
  • nodlatch/agent.py — copy repo to scratch/, run the agent there (Ollama chat call, or claude -p "…" with cwd = scratch), then diff scratch vs repo into actions
  • propose.py now calls agent.py instead of the hand-written fixture
  • Keep the fixtures for demos 2–4; they must be reproducible on stage
Phone files
  • Nothing required. Stretch: typed intent box ("only the auth change") → pre-selects Approve/Deny, human still confirms
Done when: "fix the login bug" produces a real A1/A2 proposal from the model with no hand edits, and demo 1 runs on it.

Slice 6 · Polish and rehearsal

whatever is left, minimum 1.5 h
Laptop
  • nodlatch/redact.py — mask API-key/JWT/.env-style values in review_view; mark changed secrets and reject them
  • Coloured status output; one-command demo script per scenario
Phone
  • Haptic on approve/deny, receipt animation, "SIMULATED EXECUTION — DEMO ONLY" mode for Red Light
  • Record the backup video of all four demos
Done when: all four demos run back-to-back in under four minutes, twice in a row, from a clean repo.

The four demos

1 · Selective approval
Real agent proposes A1 + A2. Approve A1, deny A2. Only A1 lands; tests pass; receipt on phone.
APPLIED (A1)
2 · Tampered artifact
Fixture. After approval, flip one byte in store/. Executor recomputes the hash.
REJECTED_ARTIFACT_HASH_MISMATCH
3 · Failing test
Fixture whose change breaks test_auth.py. Staged, tested, never written.
TESTS_FAILED_NOT_APPLIED
4 · Replay
Run execute again with the decision from demo 1.
REJECTED_REPLAY

Cut list, in order

If you are behind, drop from the top. Never cut slice 0–2.

  1. Typed/voice intent interpreter on the phone
  2. Biometric prompt (keep a confirm tap)
  3. Second transport (keep whichever of file transfer / clipboard worked first)
  4. Redaction beyond a single API-key pattern
  5. Demo 4 (replay), then demo 2 (tamper). Keep demo 1 and demo 3.
  6. Real agent: fall back to the fixture proposal and say so on the slide
